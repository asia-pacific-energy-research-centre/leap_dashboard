# AGENTS.md

This folder is intentionally scoped for building a new dashboard from the generated common ESTO comparison outputs.

## Scope

- Build dashboard code that uses `inputs/common_esto_comparison_data_sample.csv` as the primary input.
- Use `comparison_scope`, `common_flow_label`, and `common_product_label` as the dashboard axes.
- Write outputs under `outputs/<economy>/`.
- Keep the code notebook-safe with `#%%` cells and editable constants near the bottom.

## Do Not Do

- Do not use `relationship_id -> graph_id` links.
- Do not use `dashboard_chart` as a required use case.
- Do not reintroduce the old ESTO-axis mapping pipeline.
- Do not edit source mapping workbooks or common ESTO generation scripts.
- Do not inspect unrelated repo folders unless the user explicitly asks.

## Main Files

- `src/common_esto_dashboard_workflow.py` is the entry point.
- `src/common_esto_dashboard_data.py` loads and filters the common comparison data.
- `src/common_esto_dashboard_renderer.py` renders Plotly chart bundles and simple HTML dashboard pages.
- `config/common_esto_dashboard_template.json` controls page/chart group structure.
- `inputs/common_esto_comparison_data_sample.csv` is the sample input for development.

## Success Criteria

1. `outputs/<economy>/dashboards/index.html` is written.
2. `outputs/<economy>/chart_bundles/*.json` is written.
3. `outputs/<economy>/supporting_files/chart_manifest.csv` explains which rows feed each chart.
4. The dashboard can be regenerated by running `src/common_esto_dashboard_workflow.py`.


## Generated/common category handling

The dashboard must assume that common flow/product labels can be generated by graph partitioning. Do not write page rules that only work for exact ESTO labels.

Generated labels should keep component codes first, for example:

```text
07.12-07.17,07.99 Petroleum products
09.01.01,09.02.01 Electricity plants
```

Page assignment must therefore use parsed code expressions and component columns where available. The generated label is display metadata only; component membership remains the source of truth.

`config/common_esto_dashboard_template.json` should contain broad page recogniser rules, not manually enumerated charts. More specific pages should have higher precedence using lower `priority` values. Check `outputs/<economy>/supporting_files/page_assignment_summary.csv` after changing page rules.
